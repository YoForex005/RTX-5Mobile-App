Implemented behavior
- A fresh install requires a supported-directory broker selection. The selected
  broker ID is a preference; endpoints are resolved and revalidated from the
  directory rather than authorized by saved URLs or response labels.
- Selected-broker anonymous instruments, snapshots, quotes and candle history
  use a separate credential-free HTTP policy with X-Broker-ID. Exact catalog
  identifiers and precision are retained; authenticated/public caches are scoped
  separately. Context changes abort requests and invalidate authentication.
- Anonymous /ws/feed quote subscriptions reconcile acknowledgments, availability,
  opaque string sequences and quote timestamps. Heartbeats, bounded reconnect,
  demand teardown and background/foreground lifecycle are implemented.
- Anonymous /ws/v2 candles match complete channels, including dotted symbols.
  Unacknowledged/rejected channels use cancellable latest-three-bar REST reads
  every three seconds. History/live replacements retain finality and cumulative
  volume without adding duplicate bars or volume.
- One root native modal owns authentication choice, login, demo form, submission,
  hydration and recoverable errors. Active legacy auth routes delegate to it;
  old screen implementations remain inactive to preserve unrelated local work.
- Buy/Sell retains the original in-memory intent and explains that authentication
  will produce a reviewed draft, never an automatic order. Plain login, investor
  login, mutations and generic New Order do not resume an order.
- Login and demo registration use the verified extended API origin. Numeric
  login identities and response account IDs retain precision. Registration sends
  only name/email/username/password/exact broker_id, checks exact confirmation,
  uses HTTP 201 directly, ignores api_key, and performs no second login, deposit
  or account-create request.
- Public signup capability flags and supplied legal/recovery links are used.
  Duplicate submissions, rate limits, Retry-After and ambiguous creation results
  are handled without automatic registration retries.
- The existing secure session coordinator validates directory endpoints, replaces
  credentials atomically, clears omitted refresh/expiry fields, migrates compatible
  legacy identities, and rejects cancelled/late attempts. Back, dismissal,
  navigation and context/account changes invalidate pending authentication.
- /auth/me, account policy/details and account catalog hydrate before a draft is
  opened. Investor verdicts from login or hydration remain read-only.
- Central order/mutation transport guards require the current session and policy.
  Submission requires an authorized exact symbol, enabled trade mode, valid
  volume, fresh executable quote, open market and authoritative margin/risk.
  Freshness is checked again after risk reads. Missing checks fail closed.
- Logout, failed refresh and Continue as guest clear active credentials/private
  work and restore the selected broker's guest market.
